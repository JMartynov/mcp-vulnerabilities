## 1. Objective & Problem Statement

Modern MCP servers generated by SDKs provide AST protocol-level behavioral annotations on tools, including:
- `readOnlyHint`: Tool does not mutate external state.
- `destructiveHint`: Tool alters, deletes, or writes to external systems or filesystems.
- `idempotentHint`: Tool operations can be repeated safely without side effects.
- `openWorldHint`: Tool interacts with external non-deterministic web or network resources.

While `mcp-fingerprints` extracts these annotations from code ASTs and stores them in tool passports, `site_builder.py` currently strips or ignores `annotations` when serializing static shard assets (`docs/data/shards/shard_*.json`) and the catalog index. Consequently, security engineers evaluating servers on `docs/index.html` cannot see whether a tool is destructive or read-only, forcing manual source code audits.

This task integrates **AST Protocol Behavior Annotations** across the entire pipeline:
1. Updates `site_builder.py` and `catalog.py` to extract and preserve tool annotations in shards and summarize them in `mcp_catalog_index.json`.
2. Surfaces protocol hint badges (`🛡️ Read-Only`, `⚠️ Destructive`, `🔄 Idempotent`, `🌍 Open World`) in the `#server-modal` alongside CVSS/OSV scores and parameter schemas.

## 2. Detailed Technical Requirements

### 2.1 Shard & Catalog Serialization Pipeline (`src/mcp_vulnerabilities/site_builder.py`)
1. In `src/mcp_vulnerabilities/site_builder.py`, within `_serialize_version_security_record()` or tool serialization logic:
   - Ensure `ToolSecurityAssessment.annotations` (dictionary of `str -> bool`) is preserved when writing shard JSON files:
     ```python
     "annotations": {
         "readOnlyHint": bool(t.annotations.get("readOnlyHint", False)),
         "destructiveHint": bool(t.annotations.get("destructiveHint", False)),
         "idempotentHint": bool(t.annotations.get("idempotentHint", False)),
         "openWorldHint": bool(t.annotations.get("openWorldHint", False)),
     }
     ```
2. In `mcp_catalog_index.json` summary records:
   - Aggregate protocol hint counts across representative version tools:
     ```python
     "protocol_hints": {
         "has_destructive": any(t.get("annotations", {}).get("destructiveHint") for t in tools),
         "destructive_count": sum(1 for t in tools if t.get("annotations", {}).get("destructiveHint")),
         "read_only_count": sum(1 for t in tools if t.get("annotations", {}).get("readOnlyHint")),
     }
     ```
3. Support backward compatibility: if a passport has no annotations or annotations is None, default to an empty dictionary without throwing exceptions.

### 2.2 Server Modal Tool Rendering (`docs/app.js`)
1. Inside `openServerModal()` -> tool rendering section:
   - Inspect `tool.annotations` for each tool in the selected version.
   - Generate protocol hint pills:
     * `readOnlyHint === true`:
       `<span class="badge badge-hint badge-readonly" title="Declared safe read-only operation">🛡️ Read-Only</span>`
     * `destructiveHint === true`:
       `<span class="badge badge-hint badge-destructive" title="Declared destructive operation (modifies/deletes state)">⚠️ Destructive</span>`
     * `idempotentHint === true`:
       `<span class="badge badge-hint badge-idempotent" title="Declared idempotent operation (safe to repeat)">🔄 Idempotent</span>`
     * `openWorldHint === true`:
       `<span class="badge badge-hint badge-openworld" title="Declared open-world interaction (fetches external network data)">🌍 Open World</span>`
2. Render hint badges in the tool card header immediately adjacent to the tool risk badge (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).
3. In `#server-modal` top metadata bar, if `has_destructive` is true, render a summary pill: `<span class="badge badge-warning" title="Server exports tools with destructive capabilities">⚠️ Contains Destructive Tools</span>`.
